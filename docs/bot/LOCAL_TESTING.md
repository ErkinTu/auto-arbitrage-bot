# Локальная проверка бота: как тестируем рассылку

Как прогнать бота «от начала до конца» на своей машине, не дожидаясь парса из
интернета. Отработано 22.10.2026 на этапах 1–2 плана (карточки с фото, дайджест).

---

## 1. Что используем

| Что | Значение |
|---|---|
| Бот | `@lyambarbot` — **тестовый**, не боевой; его токен в локальном `.env`. Поднимать локально можно |
| Тест-аккаунты | `userera` (telegram_id 7229265363) — прогон «с нуля»: старт → триал → пуши; `esaadatbekov` (941234386) — приглашён userera, состоит в группе (`member`, без триала); `AccErkin` (1184591481) — основной аккаунт владельца, `member`, свой фильтр «КР, ниже рынка на 10%» от 30.07 |
| База | локальный Postgres в docker (`localhost:5436`, из `.env`) — копия прода с отставанием; фото (`image_url`) есть только у объявлений, увиденных после 22.10 |

## 2. Запуск

```bash
cd car-analytics-mvp
docker compose build && docker compose up -d   # migrate → api, worker, bot
docker logs -f car_analytics_bot               # ждать «bot poller started»
```

Для теста в локальном `.env` удобно (**вернуть после теста**):

- `BOT_FRESH_INTERVAL_MINUTES=3` — цикл раз в 3 мин вместо 10;
- `BOT_GROUP_MIN_LISTINGS=3` — включить дайджест (в коде дефолт 0).

После правки кода — `docker compose build bot && docker compose up -d --no-deps --force-recreate bot`.
Старт контейнера 2–5 мин: `uv run` докачивает dev-пакеты (ruff и др.) — известная
особенность образа (см. TODO: `--no-dev`).

`pytest` читает тот же `.env`: с `BOT_FRESH_INTERVAL_MINUTES=3` падает
`test_bot_poller_pacing` — запускать `BOT_FRESH_INTERVAL_MINUTES=10 uv run pytest -q`.

## 3. Чистый старт пользователя

Удалить пользователя из **локальной** базы (каскадом уйдут фильтры, отправки,
события, чёрный список, платежи):

```sql
UPDATE bot_users SET referrer_id = NULL WHERE referrer_id = <id>;
DELETE FROM bot_users WHERE telegram_id = 7229265363;
```

Затем с этого аккаунта `/start` → витрина (3 карточки) → кнопка триала → базовый
фильтр «КР, ниже рынка на 20%» + превью до 3 карточек. Объявления, появившиеся в
базе ДО создания фильтра, человеку не придут (точка отсчёта фильтра) — поток не
сыплется на новичка.

## 4. Тестовая рассылка без парса — `scripts/dev_inject.py`

Клонирует подходящие человеку объявления в строки `devtest-*` с публикацией
«сейчас» → следующий цикл бота разошлёт их как новые. Отбор — теми же функциями,
что у рассылки (его фильтры, «ниже рынка», полнота, чёрный список). Клоны не
попадают в статистику и витрину; ссылка — на настоящее объявление. Работает только
с локальной базой (иначе отказ).

```bash
PYTHONPATH=. uv run python scripts/dev_inject.py --telegram-id 7229265363 --count 10
  --count 60              # больше потолка 50 за цикл: остаток — следующим циклом
  --brand Toyota          # одна марка
  --photo none|broken     # без фото / битая ссылка → карточка текстом
  --event price_changed   # как «подешевело»
  --cleanup               # удалить все devtest-объявления
```

Пользователь должен уже существовать и иметь фильтр (иначе скрипт так и скажет).
Скрипт берёт самые выгодные — это часто старьё «−55%»: бот такое пропускает, пока
`BOT_MAX_BELOW_MARKET_PERCENT=60`.

## 5. Как проверить, что ушло

```bash
docker logs car_analytics_bot --since 5m | grep "notifications:"
#  notifications: 4 message(s) for 13 listing(s)  ← сообщений < объявлений = дайджест
docker logs car_analytics_bot | grep "is handled. Duration"   # время ответа на нажатия
```

```sql
-- что получил человек за 5 минут: в дайджесте (batch_id есть) или карточкой
SELECT batch_id IS NOT NULL AS in_digest, count(*)
FROM sent_notifications s JOIN bot_users u ON u.id = s.user_id
WHERE u.telegram_id = 7229265363 AND s.sent_at > now() - interval '5 minutes'
GROUP BY 1;
```

Предпросмотр карточек без бота (и на проде): `cli.py preview-cards --chat-id N`
(сухой прогон; `--send` — отправить).

### Грабли прогона

- **В локальной базе живые люди** (тестовые триалы/подписчики `@lyambarbot`): перед
  прогоном изолировать — `CREATE TABLE devtest_isolation AS SELECT id, is_active
  FROM bot_users; UPDATE bot_users SET is_active=false WHERE telegram_id <> <мой>;`,
  после — вернуть из таблицы и удалить её. Проверить, что никому не положены
  пейвол/продление (флаг `is_active` их не глушит).
- **Ночью бот спит** (`BOT_ACTIVE_START_HOUR=8`): для теста — `0` в `.env`, после
  вернуть и **пересоздать `bot` и `worker` ДО** возврата `is_active` остальным.
- **Worker после рестарта сразу уходит в обслуживание lalafo** (~час) и до
  напоминаний не доходит — разово: `docker compose exec -T worker uv run python -c
  "from app.worker import send_pause_reminders; print(send_pause_reminders())"`.
- Клоны `dev_inject.py` копируют `image_urls`, но у старых оригиналов галереи нет, а
  запасной запрос по `devtest-*` id для lalafo не сработает — дотянуть галерею
  клону с оригинала (по `source_slug`).
