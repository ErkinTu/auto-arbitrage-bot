# ADR: админка + analytics-front → единая платформа под сайт

**Статус:** **принято 09.11.2026** — монорепо, сайт на **Nuxt 4** (SSR ради SEO карточек и страниц марок), админка остаётся Vue SPA. Код не переносили —
только подготовка (бэкенд `feature/public-api-hardening`, фронт
`analytics-front@feature/resilient-http`).

Связанные: `docs/api/PUBLIC_API.md` (аудит API и контракт ленты),
`docs/planning/PROJECT_ANALYSIS_SUMMARY.md` (риски нового ТЗ, в т. ч. юридический
по копированию объявлений — §4.7), `../web-site.md` (ТЗ сайта), `../demo/` (демо).

## Контекст: что есть

- `analytics-front` — Vue 3 + Vite + Pinia + Tailwind 4 + echarts, ~4 тыс.
  строк, **одна** git-ветка `main`, один коммит. По факту это админ-панель
  (Обзор / База / Юзеры / Рынок), «аналитика» — экран «Рынок».
- Типы ответов API написаны руками (`src/types/*.ts`) — расходятся со схемой
  бэкенда молча, ловится только глазами.
- Экран «Рынок» — 555 КБ JS (188 КБ gzip): echarts уже подключён модульно,
  это его минимум. Для панели терпимо, для мобильного сайта — нет.
- Админ-API строго read-only, вход по ссылке из бота, сессия в куке
  `SameSite=strict`.
- Демо сайта — один статичный HTML с выдуманными данными; дизайн-токены в нём.

## Требования

1. Сайт: mobile-first, быстрый первый экран, SEO для карточек и страниц марок.
2. Админка: удобная, быстрая, «безотказная» (не падает от сбоя одного запроса,
   переживает рестарт api), позже — пишущие действия (продлить подписку и т. п.).
3. Одна команда (1-2 человека): минимум инфраструктуры, общий код без копий.
4. Внешний API под лимитами и без утечек (номер продавца, сырые payload).

## Варианты

| | А. Всё в одном SPA | **Б. Монорепо: два приложения + общие пакеты** | В. Два независимых репо |
|---|---|---|---|
| SEO сайта | нет (SPA) | да (SSR у сайта) | да |
| Риск утечки админ-кода на сайт | высокий: один бандл, один домен | нет: разные приложения и домены | нет |
| Общие типы/UI | бесплатно | пакеты `api-client`, `ui` | копии, расхождения |
| Сложность | низкая | средняя (pnpm workspaces) | низкая, но дублирование растёт |
| Отказоустойчивость | падение сборки = падают оба | независимые деплои | независимые |

## Решение: **Б, один сайт** (уточнено владельцем 09.11.2026)

**Админка — не отдельное приложение, а раздел того же сайта** с тем же дизайном
и компонентами: администратор видит сайт как все, плюс пункты «Обзор / Юзеры /
База» в меню. Отдельного дизайна и функционала «под админа» не делаем.

```
analytics-front/
  apps/web/                 ← Nuxt 4: сайт по демо + раздел /admin/* (бывший src/)
  packages/api-client/      ← типы из OpenAPI (openapi-typescript) + http.ts
  packages/ui/              ← токены (demo/tokens.css) и Ui*-компоненты
  src/ (старая SPA)         ← живёт до переноса экранов в apps/web, потом удаляется
```

Почему так:

- **Vue остаётся.** Nuxt — тот же Vue 3 с SSR для SEO; `.vue`-компоненты и Pinia
  переносятся без переписывания логики.
- **Один сайт, роль — свойство пользователя.** Раздел `/admin/*` рендерится
  только на клиенте (`routeRules: { '/admin/**': { ssr: false } }`), закрыт от
  поисковиков (`noindex`, `robots.txt`), гейт — та же сессия и `current_admin`
  на бэкенде. Меню админа показывается по `/auth/me` (`is_admin`).
- **Цена одного origin:** XSS на публичной части дотянулся бы до админских
  запросов (кука httpOnly, но запрос из страницы она сопроводит). Поэтому:
  тексты объявлений — чужие данные, **никогда `v-html`**; строгий CSP на сайте
  (`script-src 'self'`); пишущие админ-ручки (когда появятся) — с CSRF-токеном
  и журналом `admin_audit_log`.
- **Вход — через Telegram-бота** (решение владельца): как у админки сейчас —
  бот выдаёт одноразовую ссылку → сессия в httpOnly-куке. Админский вход
  обобщается до пользовательского (`user_sessions` + роль), отдельной
  регистрации по паролю/почте нет. На сайте фильтры детальнее, чем в боте, —
  бот остаётся каналом уведомлений; формат обмена фильтрами — отдельный этап.
- **`api-client` из OpenAPI**: генерация типов из схемы FastAPI; `http.ts` с
  повторами/таймаутом переезжает туда же.
- **Графики сайта** — uPlot/SVG; echarts только в админ-разделе (лениво).

### Роли (решение владельца 09.11.2026, ветка `feature/roles`)

| Роль | Кто | Что открыто |
|---|---|---|
| `guest` | не вошёл | лента, карточки **с оценкой рынка** (средняя и отклонение), страница авто, «лучшее», каталог |
| `user` | вошёл через бота (`/login`), доступа нет | то же (личное — позже) |
| `subscriber` | активный доступ, **как у пушей бота**: группа / оплата / триал | + графики и аналитика: `market/*`, `estimate`, `price-trend`, `dashboard/*`, история цены в карточке |
| `admin` | `bot_users.is_superuser` | всё + `admin/*` (пользователи, платежи, парсеры) |

- Гейт — на бэкенде, на роутере (`api/roles.py::require_subscriber`), не на
  фронте: спрятанная кнопка не защищает данные. 401 = не вошёл, 403 = мало роли.
- Роль не хранится в сессии, считается на каждом запросе (`site_auth.role_of`):
  истекла подписка или снят флаг — действует сразу.
- `access_status='member'` засчитывается только при `last_access_check_at` —
  это дефолт колонки, и без проверки ботом доступа он не даёт.
- Сессия: кука `sk_session` (httpOnly, Secure, SameSite=Lax — человек приходит
  по ссылкам из Telegram), 30 дней; админу — 12 ч. Админские ручки принимают и
  старую куку панели, и сессию сайта с ролью admin.
- Ответ, зависящий от роли (карточка), — `Cache-Control: private` + `Vary: Cookie`;
  ручки подписчиков — `private`: общий кэш не отдаст гостю данные подписчика.
- `/login` в боте открыт всем (`ENTRY_COMMANDS`), в меню команд — только при `SITE_URL`.

### Домен (фундамент до покупки)

Адрес сайта нигде не зашит: бэкенд — `SITE_URL`, Nuxt — `NUXT_PUBLIC_SITE_URL`
и `NUXT_PUBLIC_API_BASE`, Caddy — `{$SITE_DOMAIN}`. Пока —
`skupka.63-182-28-250.sslip.io` (sslip.io, как у админки и вебхука). Переезд
на свой домен = DNS A-запись + три переменные + `caddy reload`; канонические
ссылки, `sitemap.xml` и Open Graph строятся от `SITE_URL`, поэтому SEO
переедет без правок кода. Старый `admin.…sslip.io` после переноса панели —
редирект на `<сайт>/admin`.

### Карточка (решения владельца 09.11.2026)

- Базовая информация объявления + наша аналитика поверх (оценка рынка).
- Аналитика — **средняя цена рынка и отклонение** от неё в $ и %; категории
  «выгодно / в рынке / дорого» — только цвет бейджа, порог настраивается.
- Тип продавца — показываем, если его отдаёт источник.
- Снятые с продажи — в избранном остаются: тусклые, с меткой «Снято», часть
  полей скрыта.
- Фото — напрямую с CDN источника (без своего ресайзера).

### Бэкенд под это

- Публичный роутер `app/api/public/` (лента, карточка, «лучшие») — по контракту
  `PUBLIC_API.md §5`; админский `app/api/admin/` не трогаем.
- Общая логика ленты/оценки — в `services/`, переиспользуя код бота
  (`matching.market_estimate`, `bot/showcase.py`), а не копируя: иначе сайт и бот
  покажут разную «выгоду» на одну машину.
- Когда админке понадобятся пишущие действия: отдельная таблица
  `admin_audit_log` (кто, что, когда, до/после), CSRF-токен в заголовке поверх
  `SameSite=strict`, подтверждение опасных действий. До этого — read-only, как
  сейчас.
- Redis — только когда `api` станет многопроцессным (`PUBLIC_API.md §7`).

### «Быстро и безотказно» — конкретно

| Слой | Мера | Где |
|---|---|---|
| Сеть | таймаут, повтор GET при 429/5xx с `Retry-After`, склейка одинаковых GET | `http.ts` — **сделано** |
| API | лимиты, кэш + single-flight, `statement_timeout`, readiness | бэкенд — **сделано** |
| Данные | stale-while-revalidate на клиенте (показать прошлое, тихо обновить) | `api-client`, этап 1 |
| UI | скелетоны вместо спиннеров, ошибка одного блока не валит экран (error boundary на виджет) | `packages/ui`, этап 1 |
| Сборка | бюджет бандла в CI (сайт: первый экран ≤ 150 КБ gzip) | этап 2 |
| Деплой | статика сайта/админки — атомарная замена каталога (`dist.new` → `dist`), откат = вернуть прошлый | `DEPLOY.md`, этап 2 |

## Стек (утверждён 09.11.2026)

База: Vue 3.5, Vite, Pinia, Tailwind 4 (есть) + **@tanstack/vue-query** (кэш
серверных данных, SWR, повторы), **@vueuse/core**, **openapi-typescript +
openapi-fetch** (типы из схемы FastAPI), **valibot**, **unplugin-icons** (lucide).
Сайт: **Nuxt 4**, **@nuxt/image**, **@tanstack/vue-virtual** (лента),
**Reka UI** (доступные примитивы), **vaul-vue** (нижняя панель), **embla-carousel-vue**,
**uPlot** (графики сайта; echarts — только админка), **@vite-pwa/nuxt**.
Качество: Vitest + @vue/test-utils, Playwright, MSW, ESLint/oxlint,
@sentry/vue, size-limit (бюджет первого экрана 150 КБ gzip).
Не берём: axios, moment/dayjs (есть `Intl`), lodash, Vuetify/Element/Quasar.

Дизайн-система — `../demo/DESIGN_SYSTEM.md` + `../demo/tokens.css` (ветка
`design/strict-premium` репо `demo`): токены двух тем, компоненты ядра, список
доработок доступности, которых нет в демо.

## Последствия

- `+` Сайт и админка развиваются и падают независимо; общий код один раз.
- `+` Типы из схемы — изменение API ломает сборку фронта, а не прод.
- `−` Монорепо — новая для проекта механика (workspaces, генерация типов).
- `−` Nuxt-сайту нужен Node-процесс на сервере (SSR) — ещё ~150 МБ памяти на
  Lightsail 2 ГБ. Альтернатива — пререндер страниц марок + SPA для ленты
  (без Node на проде); выбор — на этапе 3 по замеру памяти.
