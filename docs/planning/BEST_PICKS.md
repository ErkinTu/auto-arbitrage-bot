# «Лучшее сейчас» — как выбираем (сайт `/public/best` и бот `/best`)

Одна логика на двоих: `app/services/best_picks.py` (чистый модуль, без БД).
Решения владельца 12.11.2026. Сайт собирает кандидатов в `public_feed.best_now`,
бот — в `bot/showcase.compute_showcase` (дальше проверка «снято ли» — `verified`).

## Идея
Лучшее ≠ самое дешёвое. Скидка 50 %+ — это битая машина, ошибка цены или рассрочка.
Лучшее = **выгодно по-настоящему** + **выглядит надёжно** + **свежее**.

## 1. Допуск (жёсткие фильтры)
| Условие | Значение |
|---|---|
| Фото | ≥ 3 (никогда не ослабляется) |
| Год | ≥ 2005; 2005–2017 — только при скоре ≥ 0,55; «новая» = 2018+ (не старше 8 лет) |
| База рынка | ≥ 20 похожих (15 — только в ярусе 3) |
| Скидка к рынку | в коридоре яруса (ниже); > 45 % не берём нигде |
| Прочее | не зарубежная, цена не мусорная (≥ $500), не повтор (та же машина на 2 источниках → один) |

## 2. Ярусы (нужны, если хороших мало)
Идём сверху вниз; позиции прежних ярусов всегда выше новых.

| Ярус | Свежесть | Скидка | База |
|---|---|---|---|
| 0 основной | ≤ 24 ч | −20…−35 % | ≥ 20 |
| 1 мягкий | ≤ 24 ч | −15…−40 % | ≥ 20 |
| 2 | ≤ 48 ч | −15…−40 % | ≥ 20 |
| 3 крайний | ≤ 72 ч | −10…−45 % | ≥ 15 |

Пул расширяется с 24 до 72 ч только если по 24 ч набралось меньше 12.

## 3. Скор (0…1) — порядок внутри яруса
`0,40·скидка + 0,30·год + 0,15·фото + 0,15·доверие`
- скидка: 1 на плато −20…−35 %, спад до 0 к −8 % и −50 %;
- год (возраст): ≤5 лет 1,0 · ≤8 0,8 · ≤11 0,6 · ≤16 0,4 · ≤21 0,2 · старше 0;
- фото: (n−2)/6, 8+ фото — полный балл;
- доверие: 0,6·log10(база/20) (0 при 20, 1 при 200) + 0,4 за известный пробег.

## 4. Порядок карусели (12 мест)
1. **Первые 5 — новые** (2018+, ярус ≤ 2) по (ярус, скор).
2. Дальше — **старые** (2005–2017, скор ≥ 0,55).
3. Остаток добиваем новыми (в т.ч. ярус 3).
4. Не больше **2 машин одной модели**.
Бот: пул 24 → проверка у источника выкидывает снятые → показываем 12.

## 5. Если 12 не набралось
Ярусы 1→3 расширяют условия. **Дальше не добиваем мусором:** фото ≥ 3 и потолок
скидки не ослабляются. Меньше 12 — отдаём сколько есть (в логе warning
`best picks: набралось N из 12`), пусто — карусель на сайте скрыта, в боте прежний
пустой ответ. Чаще всего дефицит ночью и утром (мало свежих объявлений).

## 6. Где что лежит
- Настройки (`.env`, дефолты в `core/config.py`): `BEST_MIN_PHOTOS=3`, `BEST_NEW_AGE_YEARS=8`,
  `BEST_NEW_SLOTS=5`, `BEST_MIN_YEAR=2005`, `BEST_OLD_MIN_SCORE=0.55`, `BEST_MAX_PER_MODEL=2`;
  ярусы и веса — константы `TIERS`, `W_*` в `best_picks.py`.
- Тесты: `tests/test_best_picks.py` (чистые), `test_public_feed.py::test_site_best_*`;
  старые тесты витрины бота идут с фикстурой `lenient_best` (мягкие пороги).
- Кэш сайта: ответ `/public/best` прогревается фоном (`services/warmup.py`), TTL 300 с.

## 7. Проверять «снято ли» чаще — сделано 12.11.2026 (`services/liveness.py`, ветка `feature/liveness`)

Реализация: поток `liveness` в worker — «Лучшее» сайта раз в 5 мин, избранное (`watched_listings`) раз в 30 мин,
страница авто по открытию (не чаще раза в час). mashina — API карточки `…/v1/ads/{slug}/detail` (~5 КБ), lalafo —
карточка через прокси. Снятое: `is_active=false`, номер продавца остаётся (решение владельца). Ниже — исходный план.

Снятое объявление остаётся в «лучших», пока его не деактивирует обход (цикл бота — 10 мин на
свежие страницы, полный обход — раз в неделю). Нужно:
- **Лучшие:** отдельная быстрая проверка 12 позиций карусели у источника раз в 3–5 мин
  (та же `verify`, что у витрины бота); снятое → `is_active=false`, кэш ключа сбросить.
- **Избранное:** сервер не знает id (они в localStorage). Копить «наблюдаемые» id из запросов
  `/public/listings?ids=` (TTL несколько часов) и проверять их тем же заданием, реже (≈ 15 мин).
- Лимит запросов к источникам (прокси платный у lalafo!), паузы как у обхода.
