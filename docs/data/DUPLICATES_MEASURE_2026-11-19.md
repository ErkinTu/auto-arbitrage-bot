Скрипты: `scripts/analysis/dups_measure.py` (пары-кандидаты), `scripts/analysis/dups_validate.py`
(проверка по фото). Выборка для ручной проверки — `dups_sample_2026-11-19.csv` (484 пары, ссылки на сайт,

## Коротко

- Активных объявлений **123 960** (lalafo 68 034, mashina 55 926).
- **Точно подтверждённые дубли — 1,3 % активных** (≈1 580 «лишних» объявлений): то же фото (тот же файл)
  внутри одной площадки. Это нижняя граница.
- **Грубая оценка всех дублей — 6–10 % активных** (≈ 8–12 тыс. лишних): по долям совпадения фото в выборках.
- **Дубли между mashina и lalafo нынешними данными почти не находятся** — у площадок разные файлы фото, а
  телефон mashina мы не знаем (берётся только по нажатию в боте). Твои примеры 342318 ↔ 350817 и
  326654 ↔ 326537 — именно такие. Для них нужен перцептивный хэш фото (задача 27, DU-2).
- **Новые машины (пробег < 1000 км) дают 89 % всех «похожих» пар** (222 тыс.): это склады дилеров —
  одинаковые модель, год, цена, пробег 0. Как дубли их считать нельзя.

## Как искали

Пары-кандидаты среди активных: та же марка, модель, год, совместимое топливо, цена ±7 %, появились в пределах
90 дней, и хотя бы одно из: пробег ±1,5 % (или ±1000 км), общий признак телефона (`seller_phone_hash`), тот же
файл главного фото, то же описание (≥ 40 знаков). Без цен-выбросов (`price_suspect`).

Покрытие признаков у активных:

|---|---|---|---|---|
| lalafo | 58 % | 22 % | 100 % | 52 % |
| mashina | 0 % | 91 % | 98 % | 100 % |

## Насколько признаки надёжны

Проверка без ручной разметки: у каждой пары сравнили первые три фото перцептивным хэшем (dHash, расстояние
≤ 8 из 64 — «фото совпали»). Все 5 контрольных пар из разбора (345153/344978, 342318/350817,
326654/326537/324202) так опознаются. Пары с разными фото могут быть и той же машиной, снятой заново —
поэтому это оценка снизу.

| Правило | Пар среди активных | Фото совпали |
|---|---|---|
| Тот же файл главного фото | 2 964 | **88 из 88** |
| Пробег совпал точно, некруглый (≥ 1000 км) | 729 | 43 из 67 (64 %) |
| Общий телефон + пробег близко, некруглый | 813 | 35 из 70 (50 %) |
| Общий телефон + пробег близко, круглый | 1 082 | 27 из 69 (39 %) |
| Только пробег близко, круглый (90 000 / 91 000) | 17 747 | 8 из 40 (20 %) |
| Только пробег близко, некруглый | 10 395 | 5 из 38 (13 %) |
| То же описание | — | 3 из 26 (шаблоны дилеров) |
| Новые машины < 1000 км без других признаков | 222 042 | 1 из 40 |

Вывод: **«вероятно» (точность ≥ 95 %) сейчас даёт только «тот же файл фото».** Телефон в одиночку — нет:
у дилера один номер на много одинаковых машин. Описание — нет: шаблоны. Пробег без фото — 13–64 %.

## Что из этого следует для метки «возможный дубль» (задача 20, DU-1)

| Уровень | Правило | Объявлений с меткой |
|---|---|---|
| вероятно | тот же файл фото (кроме новых < 1000 км) | ≈ 2 840 |
| возможно | тот же файл фото у новых; пробег совпал точно (некруглый); телефон + близкий некруглый пробег | ≈ 2 540 |

Итого ≈ 5 200 объявлений (4 % активных). Твои примеры: из пяти пар такая метка найдёт только
326654 ↔ 324202 (тот же файл на mashina); Prius 345153/344978 — «возможно», если у них общий телефон; два
кросс-площадочных Camry — не найдёт.

**Решение, которое нужно перед задачей 20:**
1. Делать метку на нынешних признаках (быстро, внутри площадок) — или сначала перцептивный хэш главного фото
   (задача 27): разово ≈ 124 тыс. картинок по 25–60 КБ (≈ 4–5 ГБ с CDN, растянуть на ночь-две), дальше
   ≈ 2,7 тыс. в сутки; хранить только хэш (8 байт), не сами фото. С хэшем находятся и дубли между mashina и
   lalafo, и перезаливы с другими файлами.
2. Показывать ли «возможно» (точность 40–64 %) людям — или только «вероятно», а «возможно» — в админке.

## Проверка хэша фото между площадками и стоимость (19.11, вопросы владельца)

**Хэш не «одинаковый байт в байт», а близкий:** mashina ставит водяной знак, размеры у площадок разные, поэтому
сравниваем расстояние dHash (0–64), а не равенство. Распределение на 484 парах двугорбое и чёткое:
совпавшие снимки — **0–4** (в основном ровно 0), разные машины — **16–31**, между ними почти пусто (одна пара — 8).
Пары mashina ↔ lalafo: совпали 49 из 92, у большинства расстояние 0. Все 5 контрольных пар владельца — 0–3.
Глазами проверено (`dups_cross_check_2026-11-19.png`): расстояние 0 — тот же снимок BMW X5 (на mashina с водяным
знаком); расстояние 2 — тот же Range Rover, но совпал **не главный кадр, а другой из первых трёх**; расстояние 25 —
разные машины. Вывод: хэшировать **первые 3 фото**, порог ≤ 8.

**Деньги:** картинки lalafo (`img5.lalafo.com`) отдаются серверу напрямую, **без платного прокси** (проверено с
прода: 200, 66 КБ, 0,1 с; прокси DataImpulse $1/ГБ нужен только для API lalafo). Входящий трафик Lightsail не
тарифицируется. Объём: разово ≈ 124 тыс. × 3 кадра × ~50 КБ ≈ 18 ГБ (растянуть на сутки, ~5 запросов/с — щадяще
для CDN), дальше ≈ 0,4 ГБ/сутки. Хранить — только хэш (8 байт на кадр).

**Решение владельца 19.11:** на сайте показывать **только «вероятно»**; «возможно» — в админку, людям не показывать.

## Метка «Вероятно, та же машина» на хэшах фото — проверка (19.11, задачи 27 и 20)

Код — ветка `feature/photo-hash`: `services/photo_hashes.py` (хэши), `services/same_car.py` (пары), фронт —
`feature/same-car`. Правило: та же марка, модель, год; совпал какой-то из первых 3 кадров (dHash ≤ 8); топливо и
пробег не противоречат (разница ≤ max(5000 км, 10 %)); кадр, точно совпавший у > 5 объявлений, и объявления
с > 5 совпадениями (склады, шаблоны салонов) не считаются; новые (< 1000 км) не хэшируются.

Проверка на копии прода: случайные блоки «марка+модель+год» по 10–400 объявлений + блоки контрольных пар —
**6 182 объявления** (18,5 тыс. кадров, скачалось 99,7 %, lalafo локально тоже отдаётся без прокси).

| | |
|---|---|
| Пар «та же машина» | 872 (из них mashina ↔ lalafo — 475) |
| Активных с меткой (есть та же машина среди активных) | **1 323 из 6 142 — 22 %** |
| Глазами (4 листа по 12 пар, случайно; пример — `same_car_check_2026-11-19.jpg`) | **48 из 48 — тот же снимок той же машины** |
| Контрольные пары владельца | все 5 найдены: 342318/350817 — 0, 326654/326537/324202 — 0–3, Prius 345153/344978 — 3 |
| Пересчёт всех пар на объёме прода (~105 тыс., ~6 млн пар в блоках) | ~3 с |

Вывод: дублей заметно больше, чем оценка 6–10 % в начале отчёта — та оценка опиралась на совпадение файла и
пробега; главный источник — одна машина одновременно на mashina и lalafo. Точность метки на проверенной выборке
— 100 % (48/48; граница снизу для «≥ 95 %» при такой выборке — ~93 %, нужен ещё лист-другой у владельца).

Бэкфилл после выката: поток `photo-hash` в worker сам пройдёт ≈ 105 тыс. активных (новые первыми) за ≈ 18–20 ч
при 5 запросах/с; метка появляется по мере хэширования (пересчёт пар — раз в час).
