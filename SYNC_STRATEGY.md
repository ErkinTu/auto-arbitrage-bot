# Sync Strategy

Короткая стратегия загрузки и обновления объявлений.

## 1. Первичная загрузка

Для новой марки один раз запускаем `full`:

```bash
uv run python -m app.cli sync --brand Toyota --mode full --page-size 100 --max-pages 100 --max-items 10000
```

Назначение:

- загрузить весь доступный каталог марки;
- создать текущие объявления;
- сохранить первую историю цен;
- получить базу для аналитики.

## 2. Регулярное обновление

Несколько раз в день запускаем `fresh`:

```bash
uv run python -m app.cli sync --brand Toyota --mode fresh --period 1d --page-size 100 --max-pages 3 --max-items 300
```

Назначение:

- быстро находить новые объявления;
- обновлять свежие карточки;
- не нагружать внешний API полным обходом.

Для 10-15 марок лучше использовать `worker` и `sync_targets`, а не ручные команды.

## 3. Редкая полная сверка

Раз в несколько дней или раз в неделю запускаем медленный `full`:

```bash
REQUEST_DELAY_SECONDS=5 uv run python -m app.cli sync --brand Toyota --mode full --page-size 100 --max-pages 100 --max-items 10000
```

Назначение:

- проверить старые объявления;
- увидеть изменения цены;
- деактивировать пропавшие объявления, если full scan дошел до конца.

Не стоит запускать full scan по всем маркам каждый день.

## 4. Total count

API возвращает `api_total`, например:

```text
api_total=6325
```

Сейчас он только логируется. Правильное улучшение: хранить его по каждой марке/target в `sync_targets`, например:

- `last_api_total`
- `last_api_total_at`

Это поможет понимать, выросла ли выдача по марке.

Важно: `api_total` не должен быть единственным критерием обновления. Даже если total не изменился, новые объявления могут заменить старые на первых страницах.

## 5. Практическая схема

Для каждой марки:

1. Один раз сделать `full`.
2. Несколько раз в день делать `fresh`.
3. Раз в неделю делать медленный `full`.
4. После больших загрузок запускать:

```bash
uv run python -m app.cli rebuild-stats
```
